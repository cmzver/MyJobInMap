# Развитие FieldWorker — 1 ноября 2026

Реализован согласованный набор предложений. Исключены чек-листы выполнения
(функция №1) и помощник при приёме заявок (функция №7).

## Что доступно

| Возможность | Где | Поведение |
|---|---|---|
| Полная диспетчерская сводка | Портал, API | SQL-агрегация по всему результату с теми же фильтрами и правами, что у списка; переходы из неназначенных заявок. |
| Сохранённые виды | Портал, API | Личные и общие виды организации. Локальные виды импортируются идемпотентно; исходные записи браузера сохраняются. Включены фильтры срока, повторов и отсутствующего исполнителя. |
| Синхронизация | Android | Просмотр всей очереди, причин ошибок, ручной повтор/отмена. Для отклонённых сервером статуса, даты и комментария доступно исправление. |
| Конфликты | Android, API | Версия заявки сохраняется в Room и outbox. Устаревшая правка получает 409. Повтор после потери ответа возвращает сохранённый результат до проверки версии. Разрешение конфликта привязано к показанной серверной версии. |
| Плановое обслуживание | Портал, API, фоновые задания | Дни/недели/месяцы, интервалы, начало/окончание, исключения, пауза, исполнитель и оборудование. Созданные заявки доступны в обычном Android-сценарии. |
| Паспорт оборудования | Портал, мобильный браузер, API | Существующие модель, серийный номер, установка, гарантия и документы дополнены QR-переходом и историей связанных работ. Оборудование привязывается в заявке и расписании. |
| Мой день | Портал и Android | Порядок посещений, адрес, плановое время, звонок, навигация и начало работы. Включены открытые заявки до выбранного дня и без даты. Android сохраняет порядок локально и отправляет при обновлении экрана. |
| SLA | Настройки организации, API, фоновые задания | Существующие правила и дедупликация сохранены. Добавлены рабочие дни, часы и исключённые даты: обычные push ждут рабочего окна, аварийные его не ждут. Календарь не изменяет нормативы сроков. |
| Материалы | Портал, API | Каталог, стоимость, остатки исполнителей, выдача/списание и расход в заявке. Numeric/Decimal, округление суммы до копеек, атомарное изменение остатка, защита от повторного запроса и межорганизационного списания. |

## Надёжность

- Изменение статуса/даты, комментарий и их ключ идемпотентности сохраняются
  одной транзакцией. Статус и комментарии выполняются в threadpool.
- Transactional outbox охватывает события заявок и уведомления о назначении,
  статусе, комментариях и SLA. Есть аренда записи, повторы с задержкой,
  сохранение ошибки и административный повтор. Доставка at-least-once:
  при падении после внешней отправки возможен повтор; event_id стабилен.
- `GET /api/outbox` и `POST /api/outbox/{id}/retry` доступны администраторам
  в их области организации. Ошибки после десяти попыток сохраняются.
- Особенность SQLite с SAVEPOINT учтена: перед вложенной транзакцией
  явно начинается внешняя транзакция; откат SLA-claim проверен тестом.
- Сессия портала сохраняет refresh, выполняет один refresh на параллельные
  401 и повторяет запросы. Сетевой сбой refresh не удаляет сессию. Пробелы
  в пароле сохраняются. После входа восстанавливается защищённая ссылка,
  в том числе переход по QR.
- Удаление пользователя с остатком материалов запрещено с понятным 409.
  Связи новых таблиц учитывают удаление пользователя, организации и адреса.
- Обновлены OpenAPI-типы портала и затронутые DTO Android; Room 12 → 13.

## Запуск и миграции

Новые ревизии Alembic: `20261102_0004` и `20261102_0005` (продолжают
существующую цепочку с префиксом 20261102). Перед запуском API требуется
`python -m app.migrate` из `server/`; Compose уже выполняет миграции
отдельным сервисом. Обновление старой схемы, откат и повторное обновление
проверены на изолированной SQLite БД. В PostgreSQL 15 проверены чистая БД,
восстановление и переход копии рабочей схемы с `20260630_0001` на
`20261102_0005`. Локальный Docker-стек обновлён до этой ревизии.
Production также обновлён: [отчёт о деплое](DEPLOYMENT_2026-11-01.md).

`OUTBOX_ENABLED=true` включён по умолчанию. Автоматические работы и SLA
используют существующий `PERIODIC_JOBS_ENABLED`; разовый проход —
`python -m app.jobs`. Firebase и VAPID требуют существующей настройки.

При месячном расписании сохраняется исходный день месяца: 31 января →
28 февраля → 31 марта. После простоя/паузы пропущенные даты догоняются
ограниченными проходами; уникальное вхождение не позволяет создать дубль.
Квота заявок организации соблюдается.

WebSocket по-прежнему рассчитан на один API-процесс. Redis Pub/Sub перед
увеличением числа процессов остаётся в ROADMAP.

  в каждом. Дополнительно проверены
  новые типизированные ответы API. Последний полный прогон с покрытием:
  **84,48%**, выше порога CI 75%.
- Портал: **81 тест**, lint, TypeScript и production build.
- Android: **178 тестов**, compile и lint; собран debug APK **2.41.0 (24100)**.
- Браузер на синтетических данных: создание расписания, расход материала,
  паспорт/QR, серверная сводка, переход к неназначенным, общий сохранённый
  вид. «Мой день» проверен при 390 × 844 без горизонтальной прокрутки.
- Portal CI расширен lint/тестами и проверкой дрейфа API-типов. Добавлен
  Android CI с compile/JVM-тестами/lint.
- `server/scripts/verify_backup_restore.py` создаёт две временные PostgreSQL
  БД, применяет миграции, выполняет pg_dump/pg_restore и проверяет данные и
  ревизию. Скрипт подключён к PostgreSQL CI и успешно выполнен локально.
  Скрипт требует CREATEDB и клиентские утилиты PostgreSQL; рабочие базы не изменяет.
- Исправлены блокировки PostgreSQL при смене статуса/даты: `FOR UPDATE OF tasks`
  не блокирует nullable-стороны eager JOIN. Целевые тесты и полный PG-прогон прошли.
  После исправления повторён регрессионный набор SQLite: **97 passed, 2 xfailed**.
- Docker-образ закреплён на Python 3.11 Bookworm с `postgresql-client-15`.
  Плавающий slim ранее установил клиент 17: его `pg_restore` отправлял
  `SET transaction_timeout = 0`, которого нет в PostgreSQL 15, и восстановление
  останавливалось. Повторная проверка с клиентом 15 прошла. CI использует PG 15.
- Healthcheck PostgreSQL явно указывает пользователя и базу; ложные ошибки
  `database "fieldworker" does not exist` устранены.
- После обновления стека проверены `/health`, портал, диспетчерская сводка,
  сохранённые виды, мой день, ТО, материалы/остатки, outbox и SLA-календарь:
  HTTP 200 с авторизацией, ответы JSON читаются. Миграционный job завершился с 0.
- Данные, количество записей в существующих таблицах и ранее заданные права
  сохранены при обновлении копии рабочей БД. Существующая миграция актов
  ожидаемо добавляет девять прав. Перед обновлением сохранён локальный дамп.
- Телефон/эмулятор не подключён: ручная проверка офлайн-сценария Android
