# Архитектура UX веб-портала

Обновлено: 28 октября 2026 года.

## Цель

Портал должен поддерживать два основных сценария:

- диспетчер и администратор работают с плотным списком заявок, массовыми операциями и фильтрами;
- исполнитель получает более простой мобильный сценарий с быстрым доступом к своим заявкам, карте и чату.

Изменения интерфейса должны сохранять существующий визуальный язык: нейтральные поверхности, один основной оранжевый акцент, стандартные элементы управления и минимум декоративных блоков.

## Реализовано

### Навигация и доступность

Мобильная навигация в `DashboardLayout` поддерживает:

- корректные `aria-expanded`, `aria-controls`, `role="dialog"` и `aria-modal`;
- закрытие по `Escape`;
- удержание фокуса внутри открытого меню;
- возврат фокуса на кнопку открытия;
- блокировку прокрутки фоновой страницы.

Меню пользователя и выбора темы сообщают состояние раскрытия вспомогательным технологиям и закрываются по `Escape`.

Для исполнителя на экранах меньше `lg` отображается нижняя навигация: «Заявки», «Карта», «Календарь», «Чат» и «Профиль». Она строится из того же реестра `menuConfig`, учитывает нижнюю безопасную область устройства и показывает функциональные счётчики заявок и чата. На страницах деталей заявки активным остаётся раздел «Заявки». Полное боковое меню сохраняет доступ к уведомлениям, поддержке и остальным разделам.

### Панель заявок

`TaskFiltersPanel` отвечает только за представление и пользовательские действия:

- поиск;
- быстрые режимы «Новые», «В работе» и «Срочные»;
- раскрываемые расширенные фильтры;
- активные фильтры;
- сводные счётчики;
- сохранённые виды.

`TasksPage` остаётся владельцем состояния, URL-синхронизации, запросов и массовых операций. Такая граница позволяет менять компоновку панели без изменения загрузки данных и бизнес-логики списка.

### Сохранённые виды

Сохранённый вид содержит:

- поисковую строку;
- адрес;
- статусы;
- приоритеты;
- исполнителей;
- сортировку;
- группировку.

На текущем этапе виды хранятся в `localStorage`. Ключ изолирован по идентификаторам пользователя и организации. Данные проверяются при чтении: неизвестные статусы, приоритеты, способы сортировки и группировки отбрасываются или заменяются безопасными значениями.

Локальное хранение выбрано как первый этап, потому что оно не требует миграции БД и изменения API. Ограничение: виды не синхронизируются между браузерами и устройствами.

### Переходы из сводок в список

Дашборд, аналитика и карта используют единый `buildTaskListUrl` для перехода к операционному списку заявок:

- показатели статусов на дашборде открывают список с соответствующим `status`;
- блок срочных заявок передаёт приоритеты `EMERGENCY` и `URGENT`;
- аналитика открывает активные заявки выбранного исполнителя;
- карта переносит в список выбранные статусы, приоритеты и исполнителя;
- исполнитель с карты переходит в раздел «Мои заявки», поскольку общий список недоступен его роли.

Генератор удаляет дубликаты, не добавляет некорректные идентификаторы исполнителей и сохраняет формат URL, который понимает `TasksPage`. Новые страницы не должны собирать эти параметры вручную.

### Состояния загрузки данных

`QueryStatePanel` задаёт единый вид начальной загрузки, ошибки и пустого результата. Состояния имеют корректные `role`, `aria-live` и `aria-busy`; при ошибке пользователь получает действие «Повторить» с блокировкой на время нового запроса.

Дашборд сохраняет независимость запросов: ошибка статистики, недельной активности или последних заявок отображается внутри соответствующего блока и не скрывает успешно загруженные данные. Аналитика сохраняет заголовок страницы во время загрузки и ошибки. Карта различает ошибку API и успешный запрос без заявок с координатами.

## URL-состояние списка

В URL синхронизируются:

- `search`;
- повторяемые `status`, `priority`, `assignee`;
- `address_id` и `address_title`;
- `sort`;
- `group`;
- `page` и `size`.

Это позволяет сохранять историю браузера, делиться ссылками и восстанавливать представление после перезагрузки. Параметры должны оставаться обратимо совместимыми: неизвестные значения игнорируются.

## Структура файлов

```text
portal/src/
  components/
    QueryStatePanel.tsx    # loading, error/retry и empty для запросов
  components/navigation/
    WorkerMobileNavigation.tsx # нижняя навигация исполнителя
  components/tasks/
    TaskFiltersPanel.tsx   # композиция фильтров и быстрых режимов
    TaskSavedViews.tsx     # выбор, создание и удаление видов
  hooks/
    useTaskSavedViews.ts   # хранение, валидация и сравнение видов
    __tests__/
      useTaskSavedViews.test.ts
  pages/
    TasksPage.tsx          # данные, состояние, URL и операции над заявками
  utils/
    taskListUrl.ts         # единая сборка ссылок на отфильтрованный список
    __tests__/
      taskListUrl.test.ts
```

## Проверка изменений

Для изменений портала обязательны:

```powershell
cd portal
npm run lint
npm test -- --run
npm run build
```

Изменения компоновки дополнительно проверяются в реальном браузере на десктопной ширине и на экране 390 × 844. Основные действия должны быть доступны с клавиатуры.
