## Позже — архитектура и данные

- **Индексы.** EXPLAIN/p95 по tenant/status/assignee/planned_date, составные
  индексы (в т.ч. под `updated_at` — инкрементальная синхронизация уже работает
  через `updated_since` + `/api/tasks/ids`).
- **Несколько процессов API.** Готово к `WEB_CONCURRENCY=N` (compose, по
  умолчанию 1): шина WebSocket, лимитер входа, DDoS-счётчик ip_guard, сброс
  кэшей (бан-лист, состав чатов) и лидер фоновых заданий — в Redis
  (`REALTIME_REDIS_ENABLED`); метрики Prometheus — multiprocess
  (`scripts/start-api.sh`). Осталось: включить N>1 на проде после проверки
  под нагрузкой; кэш геокодера и снимков домофона остаётся на процесс
  (только эффективность).
- **Android: domain → data.** Интерфейс `TasksRepository` в domain вместо
  зависимости use case от конкретного репозитория.
- **Группы пользователей.** Оценить отказ от глобальных dispatcher/worker;
  Android уже использует `AccessLevel`, основанный на `base_access`.
- **События.** Заявки рассылаются дважды — прямым `broadcast_task_*` из роутов и
  outbox из `TaskService`; оставить один путь. `act_updated` всё ещё уходит всей
  организации (у заявок мастеру — только свои).
- **OpenAPI.** В докстрингах enum-классов `models/address.py` и в описаниях полей
  `schemas/address.py` — символы-заменители (U+FFFD); исправить вместе с
  регенерацией `portal/src/types/api.generated.ts` и моделей Android.
- **Мелочи сервера.** CSV-выгрузка при `period=all` игнорирует даты; в уведомлениях
  нет `task_number` (портал готов его показать); в `UserResponse` нет `base_access`
  — финансы фильтруют исполнителей по `role`.
- **Android.** Порядок «Моего дня», переставленный без связи, уходит на сервер
  только при открытом экране — фоновая отправка; «На сегодня» сравнивает плановую
  дату строкой (сломается, если сервер начнёт отдавать её в UTC).
- **Тесты на SQLite.** Сервер и тесты всё ещё поддерживают SQLite (in-memory
  в тестах по умолчанию). Решить: оставить как быстрый режим тестов или
  перевести тесты целиком на PostgreSQL и убрать SQLite-ветки из кода.

## Эксплуатация (нужен доступ к серверу)

- **Геокодер.** Nominatim отвечает 429 на любой запрос с IP прода — работает
  через DaData (точка дома/улицы). Если понадобится точность выше — ключ
  Яндекс.Геокодера или свой Nominatim.

- **Домофоны.** Отдельный WireGuard-пир для прода и ротация ключей, сейчас пир
  общий с ноутбуком. Android-UI управления дверью (модели уже есть).
- **Telegram-бот.** С прод-сервера api.telegram.org недоступен (бот
  перезапускается); нужен бот на edge-боксе (`docker-compose.bot-edge.yml`)
  или прокси, затем `TELEGRAM_BOT_TOKEN`/`TELEGRAM_BOT_USERNAME` в API для
  уведомлений заявителю. Бот входит в API под суперадмином `admin` с
  устаревшим паролем — завести отдельный сервис-аккаунт с минимальной ролью.
  Токен бота засветился в логах (httpx) — перевыпустить.
- **Восстановление из бэкапа.** Повторить проверку на копии удалённого production.
  Локально pg_dump/pg_restore и обновление копии рабочей PostgreSQL 15 прошли;
  изолированная проверка добавлена в CI (`server/scripts/verify_backup_restore.py`).
- **Android на устройстве.** Проверить офлайн-изменение, возвращение сети и
  разрешение конфликта на телефоне; автоматические тесты прошли, устройство
  при локальной проверке не было подключено.
- Лимиты ресурсов контейнеров.
